# Agent Skills（S4b 设计）

> 状态：**Draft（S4b.1）**，待评审。目标：让 agent 拥有"**按需加载的专业能力包**"——
> 平时只花一行索引的代价知道"有这么个技能"，需要时才把正文读进上下文。

相关：[memory.md](memory.md)（索引 + 按需取回，同一套路）、[context-compaction.md](context-compaction.md)、
[mcp-seam.md](mcp-seam.md)（"名字便宜、正文贵"的最初来源）、[versioning.md](versioning.md)。

## 1. 问题与边界

产品提示词是本项目通用的工作方式；指令层（`AGENTS.md`）是**这个项目的约定**；记忆是**事实**。
技能要解决的是第四类东西：**成体系的做事方法**——"怎么发版""怎么写周报""怎么做 PDF 交付"这类
有步骤、有模板、可能带脚本的知识。它们**多数时候用不上**，全塞进提示词既贵又干扰。

**要解决**：①技能以文件形式可增删改（用户自己就能写）；②平时只注入一行索引；
③需要时模型自己把正文读进来；④"这次有哪些技能可用、读的是哪一份"可审计。

**不解决**（非目标）：

- **不是插件系统**：技能不能注册工具、不能改装配——那是 recipe 的事；
- **不是自动路由**：不做"根据任务自动挑技能"的模型外逻辑（让模型自己看索引决定），也不做事后打分；
- **不做市场/分发**：没有下载、版本约束、依赖解析；
- **不做脚本执行沙箱**：技能里的脚本仍然要过权限规则与沙箱，技能本身**不授予任何新权限**。

## 2. 决定 1：技能就是目录 + `SKILL.md`，两个作用域

```text
~/.cubus/skills/<name>/SKILL.md          用户级（跨项目复用）
<workspace>/.cubus/skills/<name>/SKILL.md 项目级（跟着仓库走，可提交）
```

- **同名时项目级覆盖用户级**（越靠近具体项目越具体，与指令层同一个优先级道理）；
- 技能目录里可以有**附件**（如 `templates/report.md`、`scripts/render.sh`）：正文里用相对路径引用它们；
- 正文是 Markdown，**不解析执行**——它就是"写给模型看的说明书"，要执行的东西走 bash 工具（受权限与沙箱约束）。

### frontmatter（最小子集，不引 YAML 依赖）

```markdown
---
name: pdf-report
description: 把评测结果渲染成 PDF 周报（含排版约定与检查清单）
when: 需要交付 PDF 时
---

# 步骤
1. ...
```

只认 `name` / `description` / `when` 三个键，`key: value` 一行一条（够用为止；要复杂结构就该写代码了）。
缺 `description` 的技能**加载期报错**：索引里没有描述，模型无法判断该不该用，等于没写。

## 3. 决定 2：只注入索引（一行一个技能）

系统提示里加一段（order **400**：角色 0 → 用户 100 → 项目 200 → 记忆 300 → **技能 400**）：

```text
## 可用技能（索引）

需要时用 read_skill 读取正文（只读你想用的那个）：

- pdf-report —— 把评测结果渲染成 PDF 周报 | 何时用：需要交付 PDF 时
- release —— 本仓库的发版流程（版本号、CHANGELOG、tag、回滚）
```

**为什么是索引**：与 MCP、记忆同一个结论。技能正文可能有几百行，全部预载等于把窗口交给"可能用不上"的东西。

## 4. 决定 3：`read_skill` 工具按需读正文与附件

```jsonc
{ "name": "pdf-report" }                          // 读 SKILL.md 正文
{ "name": "pdf-report", "file": "templates/x.md" } // 读技能目录里的附件
```

- 输出**有上限**（单次 16k 字符，超出提示用 offset 继续）——技能自己不能撑爆窗口；
- `file` **限制在技能目录内**（拒绝 `..`、绝对路径、符号链接逃逸）：技能是内容，不是越权通道；
- 找不到的 name 要**列出可用的技能名**（让模型能自己纠正），而不是只说"没有"。

## 5. 决定 4：日志记"当时有哪些技能、是哪一份"

装配快照的 `config.skills` 记**索引级事实**（不进正文）：

```jsonc
"skills": [
  { "name": "release", "source": "project", "path": ".cubus/skills/release/SKILL.md",
    "description": "本仓库的发版流程", "sha256": "…", "attachmentCount": 2 }
]
```

理由与权限规则一致：**正文只在被读时才是模型可见内容**，那时它以 `tool/result` 落进日志；
索引则每次都进提示词（`request/header.systemPrompt` 里有全文）。sha256 让"读的是哪一版"可追溯。

## 6. 决定 5：能力面不新增 kind

技能是文件（`fs` 能力即可），读取要经权限规则（S5.1）与沙箱（S5.2）——**技能不授予权限**。
分工与记忆一致：**app 读文件**（用户级技能在工作区之外，`fs` 能力按设计拒绝越界），
插件只渲染索引、注册 `read_skill` 工具。

## 7. 分解（一步一锁）

| 步骤 | 内容 | 验收 |
|---|---|---|
| S4b.1 | 本文件（设计 + 决定） | 你评审通过 |
| S4b.2 | `@cubus/skills`：目录扫描 + frontmatter 解析 + 两个作用域合并 + 索引渲染 + 装配快照记录 | 单测：缺 description 报错、项目覆盖用户、附件计数、索引上限、快照含 sha256 |
| S4b.3 | `read_skill` 工具（正文 + 附件，输出上限，路径限制） | 单测：读正文/附件、`..` 与绝对路径被拒、输出上限、未知名字列出可用技能 |
| S4b.4 | 评测：同一任务"有技能 / 无技能"两档对比（步骤数、token、是否按技能步骤做对） | 真模型脚本 + `EVALS.md` 记录（简历数字来源） |

## 8. 风险与诚实边界

- **索引也是成本**：技能多了，索引变长。上限与截断策略（默认最多 20 个技能、每个描述 ≤ 120 字符）要在 S4b.2 定死并写进快照；
- **模型可能不用技能**：那就等于没写。S4b.4 的评测正是要量这个——"有技能时它会不会真的读、读了会不会照做"；
- **技能与指令的边界**：`AGENTS.md` 是**必须遵守的约定**（每次都在提示词里），技能是**可选的做事方法**（按需加载）。
  把硬性约定写进技能 = 它可能不被加载，这是使用者的选择，文档里要讲清；
- **不做技能版本**：一份目录就是一份技能，改了就是改了（sha256 会变，日志能看出差异）。
